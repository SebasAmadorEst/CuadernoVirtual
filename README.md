# Cuaderno Interactivo Virtual de Física III

## Movimiento Oscilatorio, M.A.S. y Oscilaciones Amortiguadas

Cuaderno digital educativo para estudiar Física III mediante una experiencia visual semejante a un cuaderno físico. El proyecto combina contenido académico, deducciones matemáticas, ejercicios resueltos, tablas comparativas, simuladores interactivos, gráficas canvas, quizzes, glosario y navegación por páginas.

El sistema está diseñado como una aplicación web estática y progresiva: no requiere backend, base de datos ni proceso de compilación.

---

## 1. Objetivo del proyecto

El cuaderno busca conectar tres niveles de aprendizaje:

1. **Teoría:** definiciones, ecuaciones, modelos físicos, aproximaciones y contexto histórico.
2. **Procedimiento:** resolución de ejercicios mediante datos, incógnitas, fórmulas, despejes, resultados y validación.
3. **Experimentación virtual:** simulaciones, parámetros ajustables, planos cartesianos, energía, fase, amortiguamiento y resonancia.

El eje académico es el estudio de:

- Movimiento oscilatorio y periódico.
- Movimiento Armónico Simple, M.A.S.
- Sistema masa-resorte.
- Péndulo simple.
- Oscilaciones amortiguadas.
- Oscilaciones forzadas y resonancia.
- Energía mecánica, potencia y disipación.

## 4. Arquitectura técnica

El proyecto es una aplicación estática organizada como una SPA ligera basada en secciones HTML.

### Tecnologías

- HTML5.
- CSS3.
- JavaScript moderno sin framework.
- Canvas 2D.
- SVG para algunas ilustraciones académicas.
- KaTeX para fórmulas matemáticas.
- Nerdamer para derivaciones simbólicas.
- Font Awesome para iconografía.
- Google Fonts: Fira Code, Inter y Outfit.
- Web App Manifest.
- Service Worker para caché y funcionamiento tipo PWA.

### Flujo general

1. El navegador carga `index.html`.
2. Se cargan estilos, fuentes, KaTeX y scripts externos.
3. Se inicializa el controlador principal en `js/app.js`.
4. Se crean los motores de simulación.
5. Se preparan navegación, eventos, quizzes y selectores.
6. Se muestran la portada o el primer pliego.
7. Al navegar se activan las páginas correspondientes.
8. Los canvas se redimensionan cuando la página se vuelve visible.
9. Las fórmulas de la página activa se procesan con KaTeX.
10. El Service Worker almacena recursos locales para futuras cargas.

## 7. Navegación

### Vista de escritorio

A partir de 1024 px se utiliza una vista de doble página:

- Pliego 1: páginas 1-2.
- Pliego 2: páginas 3-4.
- Pliego 3: páginas 5-6.
- Pliego 4: páginas 7-8.
- Pliego 5: páginas 9-10.
- Pliego 6: páginas 11-12.
- Pliego 7: páginas 13-14.
- Pliego 8: páginas 15-16.
- Pliego 9: páginas 17-18.

### Vista móvil

En pantallas menores se muestra una página individual por vez.

### Formas de navegación

- Botón anterior.
- Botón siguiente.
- Botón de inicio.
- Botón de final.
- Selector de páginas y secciones.
- Enlaces de la tabla de contenidos.
- Teclado.
- Gestos táctiles, si están habilitados por el controlador.

### Transiciones

La transición vigente es un desvanecido lento con movimiento leve:

- La página izquierda entra desde la izquierda.
- La página derecha entra desde la derecha.
- La animación se reinicia al activar una página o pliego.
- La lógica de navegación mantiene la correspondencia 1-2, 3-4, 5-6, etc.
- Se respeta `prefers-reduced-motion`.

## 8. Ejercicios y quizzes

### Método de cinco fases

Los ejercicios agrupados siguen un protocolo común:

1. Datos.
2. Incógnitas.
3. Fórmulas.
4. Despejes y resultados.
5. Validación y conclusiones.

Los ejercicios consecutivos se presentan en un selector para evitar que la página se vuelva demasiado larga o desordenada.

### Quizzes

Cada bloque de quiz contiene cinco preguntas de selección múltiple. El controlador:

- Detecta la respuesta elegida.
- Marca respuestas correctas e incorrectas.
- Muestra retroalimentación.
- Calcula el resultado.
- Permite reiniciar manualmente.
- Limpia el estado al volver a la página.

## 9. Instalación y ejecución

No se necesita instalar dependencias locales para abrir la versión básica.

### Opción rápida

Abrir `index.html` directamente en un navegador moderno.

### Opción recomendada: servidor local

Desde la raíz del proyecto:

```powershell
python -m http.server 8000
```

Después abrir:

```text
http://localhost:8000/
```

También puede utilizarse la carpeta espejo:

```text
http://localhost:8000/fisica3/
```

Servir el proyecto mediante HTTP es recomendable porque permite comprobar correctamente el Service Worker y la instalación PWA.

### Requisitos del navegador

Se recomienda un navegador actualizado con soporte para:

- Canvas 2D.
- CSS animations.
- CSS custom properties.
- ResizeObserver.
- ES6+.
- Service Worker.
- Fullscreen API.

## 10. PWA y funcionamiento offline

`manifest.json` define:

- Nombre completo.
- Nombre corto.
- Icono.
- Color de tema.
- Modo standalone.
- Página inicial.

`sw.js` guarda en caché recursos locales esenciales como:

- HTML.
- CSS.
- JavaScript.
- Imágenes principales.

### Importante sobre recursos externos

KaTeX, Font Awesome, Google Fonts y Nerdamer se cargan desde CDN o recursos externos según la configuración del HTML. Para una experiencia completamente offline convendría descargar y servir localmente esas dependencias, además de agregarlas al arreglo `ASSETS_TO_CACHE` del Service Worker.

Cuando se actualicen recursos, hay que cambiar la versión:

```js
const CACHE_NAME = 'fisica3-mas-v2';
```

Esto fuerza la creación de un caché nuevo.

## 12. Mantenimiento y cambios futuros

### Mantener las dos copias sincronizadas

Cuando se modifique cualquiera de estos archivos en la raíz, actualizar también su equivalente en `fisica3/`:

- `index.html`.
- `css/styles.css`.
- `js/app.js`.
- `js/damped-simulator.js`.
- Otros módulos JavaScript modificados.
- Imágenes o recursos utilizados por ambas versiones.

### Añadir una página

1. Crear una nueva sección con clase `notebook-page`.
2. Asignar un id como `page-19`.
3. Añadirla a la tabla de contenidos.
4. Actualizar `TOTAL_CONTENT_PAGES` solo si el controlador no lo obtiene automáticamente.
5. Añadir el nombre al arreglo `pageLabels` de `app.js`.
6. Verificar el pliego correspondiente en vista de escritorio.
7. Sincronizar la carpeta `fisica3/`.

### Añadir un ejercicio

1. Crear un `exercise-card`.
2. Asignar un `data-exercise` único.
3. Añadir una opción al `exercise-selector`.
4. Incluir las cinco fases.
5. Colocarlo dentro del `exercise-group` correcto.
6. Verificar que no se duplique en otra página.

### Añadir un quiz

1. Crear un bloque `.quiz-panel`.
2. Asignar `data-quiz-page`.
3. Agregar cinco `.quiz-question`.
4. Definir `data-answer` para cada pregunta.
5. Usar nombres de radio únicos cuando existan varios formularios.
6. Comprobar que el reinicio funcione al navegar.

### Añadir un canvas

1. Usar un id único.
2. Crear el motor correspondiente.
3. Inicializarlo después de que el DOM exista.
4. Implementar cálculo de tamaño con `getBoundingClientRect()`.
5. Redibujar al entrar en la página.
6. Añadir protección para canvas opcionales.
7. Evitar depender de una página que no esté visible.

## 14. Consideraciones conocidas

- La aplicación depende de recursos CDN para algunas bibliotecas y fuentes.
- El Service Worker funciona correctamente al servir el proyecto por HTTP o HTTPS; el comportamiento puede limitarse al abrir el archivo directamente con `file://`.
- Los simuladores utilizan Canvas y pueden requerir un redimensionamiento al hacerse visibles.
- Las fórmulas necesitan que KaTeX se haya cargado antes de ejecutar el renderizado.
- La carpeta `fisica3/` es una copia espejo y debe mantenerse actualizada.
- Los cambios de cache del Service Worker requieren incrementar `CACHE_NAME`.
- El diseño usa un área de contenido con scroll interno para conservar la proporción visual de las páginas.
